# Changelog

What changed in each version, for `/update-workflow` to show a project before it re-copies the
template. Newest first. A version that changes a config file's format says so, and ships its
migration in `scripts/migrations.mjs`.

## 0.3.0 — unreleased
Built so far: phase A, the ladder (planning above a phase), phase D, the design rung (screens
designed before their tickets), phase B, the stack and setup, and phase C, the roadmap. The
decisions are in `docs/discovery/01-brigade-0.3.0.md`.

Phase C:
- `docs/status/roadmap.md`'s starting copy has two fixed tables between `<!-- brigade:roadmap -->`
  markers, Modules (`# | Module | Depends on | Stands`) and Phases
  (`Phase | Module | Spec | Branch | Stands`), and a `## Noted for later` list. Stands is one word:
  planned, building, delivered or merged, or `blocked: <why>`.
- `tools/roadmap-format.mjs` reads the format, and doc-check refuses a table out of it (a status
  word, a module that isn't in the table, a spec or branch in the wrong shape). A roadmap without
  the markers is not checked. doc-config gains an optional `ROADMAP`.
- `/roadmap`, a new skill Claude may run itself: it checks the tables against GitHub (each phase's
  pull request by its branch, its spec, its parked tickets), proposes the status changes as a diff
  (only forward, never a blocked row), writes them on a yes, and publishes the roadmap page.
  `scripts/roadmap.mjs` does the work; `skills/roadmap/page.html` is the page's template. Its link
  is kept in `.claude/workflow.json`'s `roadmap.artifact`. Without the Artifact tool, the page is
  saved to `.git/brigade/roadmap.html`. An older roadmap is offered a conversion.
- doc-sync's phase end runs `/roadmap`.

Phase B:
- `.claude/workflow.json` gains `stack` (fixed keys, any words; an undecided part left out),
  `guard.wrappers` and `roadmap`. **The hooks must be 0.3.0 to read it**: an older plugin refuses
  the unknown keys and blocks every command.
- The guard strips the project's `guard.wrappers` (longest first, with the flags after them), so a
  block rule holds through `bunx`, `yarn dlx` and the rest. Without them: `pnpm exec`, `pnpm dlx`,
  `pnpm`, `npx`, as before. The yarn/bun known limit is gone.
- Setup reads the newest discovery doc's "Requirements and stack" table, shows it beside what the
  files say (`stackFromFiles`, `stackDisagreements`), records the stack, and writes the wrappers and
  allow rules for its package manager, from the table when there is no lockfile yet.
- `CLAUDE.md`'s starting copy has a Stack section, generated by doc-index from `stack`.
- `setup.mjs refresh`, offered by `/setup-workflow` on a set-up project: it adds what the stack
  suggests (wrappers, checks, gates, allow rules, the design rung's prompt file, `PROTOTYPE_DIR`,
  `checks.yml`), and changes or removes anything (a hand-written row, a rewritten file, an older
  `CLAUDE.md`'s Stack section) only when the owner accepts it.
- `setup.mjs docker` says whether Docker is installed and running. The skill explains Docker and
  links its installer, and never installs it. Its stack checklist has Claude write each part's
  config (a compose file and preflight row for a Docker test database), with no recipes.
- doc-sync's `tech-stack.md` row is gone: a stack change is the refresh's, with a discovery
  addendum saying why.

Phase D:
- `tools/doc-config.mjs` gains `DESIGN_DIR` (`design`), `SAMPLE_DATA_DIR` (`design/sample-data`) and
  `PROTOTYPE_DIR` (a folder inside the app, or null), all optional; `design` joins `PATH_ROOTS`.
- New templates: `docs/_templates/flow.md`, a module's flow diagram (its `**Approved:**` line, a
  screen brief under each screen, the diagram), and `docs/_templates/design-system.md`, a plain
  `DESIGN.md` for a project without Impeccable.
- A generated design index, `design/README.md`: each module's approval, its screens, and whether
  its prototype is still open.
- doc-check refuses a prototype folder without its guard (a file directly in it carrying
  `brigade:prototype-guard`).
- `/ticket-check` keeps `run-ready` off a frontend ticket while `DESIGN.md` is missing, its module's
  flow is unapproved, its screen is not in the flow, or the screen has no brief.
- Setup proposes `PROTOTYPE_DIR` from the framework (a route group where it has them) and asks
  otherwise. A project with screens gets `docs/agents/phase-run-prompt.md` with a default design
  review (Impeccable's finish reviewer when installed, a fresh subagent otherwise), named by
  `phaseRun.prompt`.
- `workflow.md`'s "The design rung" replaces "Design lead-time", and the ticket template's
  "Prototype screen" becomes "Screen", naming one of its flow's screens. `workflow.md`'s budget is
  140 lines (was 130).

Phase A:
- The glossary is `GLOSSARY.md`, the name `/grill-with-docs` writes, in place of `CONTEXT.md`. A test
  keeps the old name out of the generic files. Setup detects both: overwrite archives an old one and
  offers its terms, and merge reports a `CONTEXT.md` beside the new name.
- Discovery docs have a home: `DISCOVERY_DIR` in `tools/doc-config.mjs` (default `docs/discovery`),
  header-exempt, from the new `docs/_templates/discovery.md` (with a "Requirements and stack"
  table), and listed in a generated index, `docs/discovery/README.md`.
- doc-check refuses a commit that rewrites a committed discovery doc: a changed line, an edited
  addendum, or a deletion. A dated addendum under its title is the only change allowed, and a rename
  that keeps the text passes. A config written before 0.3.0 gets the default folder.
- A repo holding only discovery docs still counts as new, so discovery can come before setup.
- `workflow.md` has "Before the first phase": discovery, a module's planning grill and what it
  produces, module numbering, and Phase 0. The module guide's template opens with **Sources:**.
- `CLAUDE.md`'s starting copy points at the discovery index and the glossary.

## 0.2.2 — 2026-10-27
Fixes from the trials' finish review and the two existing-repo trials (overwrite, merge).
- Setup writes `.github/workflows/checks.yml`: the stop gate's checks on every push and pull
  request (install, a Prisma client if there is one, each check), so a green pull request means
  the project's own tests ran. It is project config: update never touches it, so a project set up
  before 0.2.2 does not get one from an update and writes its own.
- `/update-workflow` lists a starting file (`scaffold/`) whose plugin copy changed, as `review`,
  and never writes it. The stamp now records the starting files; an older stamp says it cannot
  list earlier changes, and the next update records them.
- A `CLAUDE.md` or `AGENTS.md` one folder down (a `docs/CLAUDE.md`) is found: overwrite names its
  archived copy for the rules carry-over (`oldRules`); merge points the new `CLAUDE.md` at it.
- The phase runner refuses plainly when the repo has no GitHub remote, and a dry run stops there
  instead of failing on a stack trace.
- `CLAUDE.md`'s commands list the dev server and the build too.
- The CI template no longer names another project's devlog entries.

## 0.2.1 — 2026-10-27
Fixes from the first trial run (an empty repo, one ticket).
- The phase runner no longer crashes when a background session ends: one call still named the
  helper step 7 renamed (`stopStray`). A new plugin test fails on any call to a name nothing defines.
- The report points at the pull request only when there is one, and holds the finish ticket as
  "built attended" instead of sending it to `/ticket-check`.
- Gotchas files are flat by default (`docs/agents/gotchas/<phase>.md`). A project that groups
  phases into modules sets `GOTCHAS_FILE` in `tools/doc-config.mjs`; without it, the flat path.
  No migration: the export is optional.
- doc-check no longer prints git's "exists on disk, but not in 'HEAD'" for each new doc.
- `/ticket-check` says its `spec-issues.json` commit needs a devlog entry, and drafts the message.

## 0.2.0 — 2026-10-27
- `/setup-workflow` and `/update-workflow`: set a project up (new, overwrite or merge) and keep its
  template files current. Each project carries a stamp, `.claude/workflow-version.json`.
- The phase runner reads the project's `phaseRun` section of `.claude/workflow.json` (build step 7, docs/development.md).
- doc-check: the baseline can list docs accepted without a header (`headers`), written once by
  `--adopt`; `--update-baseline` only shrinks that list.

## 0.1.0 — 2026-10-27
- The workflow lifted from its first project: the hooks, the doc tools, `doc-sync`, `ticket-check`
  and the phase runner, made generic (build steps 1–6, docs/development.md).
